# 协作规则

English: [workflow.md](workflow.md)

## 权限

- 这个仓库是公开的，所以不用账号也能看。
- 要推送代码，在群里把你的 GitHub 用户名发给组长。你会收到一封邀请邮件，接受它。
- 在那之前，先 fork 这个仓库，再从你的 fork 发 pull request。

## 分支和 pull request

- `main` 始终能运行。只有组长往 `main` 合并。
- 每项工作开一个分支，用你的分工字母开头：`d/tfidf-models`、`e/corn-head`。
- 尽早发 pull request，并且保持小：不超过一项任务。标题里写任务编号，例如 “D2 TF-IDF models”。
- 由你的搭档或组长审阅。由组长合并。
- 每天早上把 `main` 合并进你的分支。

## 文件

- 每个文件只有一个负责人。[README](../README.zh-CN.md) 里的仓库结构写明了是谁。需要改别人的文件时，找负责人。
- 这个仓库里不放数据、模型权重、录制文件和 slides。数据和权重由 `scripts/download_data.py` 获取。
- 不放个人信息：学号、邮箱、电话、签名、照片都不放。访问令牌也不放。
- 不写死路径。用 [interfaces.zh-CN.md](interfaces.zh-CN.md) 里的环境变量。
- 每个页面旁边都有一个中文版（`name.zh-CN.md`）。以英文版为准。你新增或修改了页面，就告诉组长，由组长同步中文版。

## 运行和结果

- 每次运行都从一个配置启动，并通过 `levellens.results` 向 `results/runs.jsonl` 写入一行。不要手工编辑这个文件。
- 随机种子固定。数据划分由组长保存一次，所有模型读取。绝不重新划分。
- 测试集只用来出最终数字。设置在验证集上选，或者在训练集上用交叉验证选。
- GPU 作业都经过分工 C。把配置和命令交过去。C 把作业排进队列，再交回结果行。

## 代码

- 每个公开函数都有文档字符串。类型标注在有帮助的地方加。
- 设置写在配置里，不写在代码里。
- 每个模块一个小测试：形状、取值范围、一个已知结果。
- 开源代码可以复用，前提是它的许可证允许。在文件开头的注释里写明出处，并加进 README 的致谢。
- 视频里你要讲自己的部分，所以要保证你能讲清自己代码的每一部分。

## 沟通

- 卡住超过一小时？在群里说。
- 一项任务做完，就在你那一份的 issue 里打勾。结果一出来就发到群里：一个数字或一张图就够。
- 如果你这一份比估算多出 3 小时以上，告诉组长。组长会把一项任务移给用时偏少的那一份。
- 计划的变动由组长决定，并在当天写进这个仓库。
